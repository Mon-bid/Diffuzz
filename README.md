# Diffuzz

一个运行在 Chrome DevTools 中的轻量级**授权测试**请求变异与响应差异分析工具。
无需配置代理、无需启动 Burp，直接复用浏览器现有登录态（Cookie / CSRF Token）。

> ⚠️ **仅用于已获得书面授权的渗透测试场景。** 使用者需自行确保对目标拥有合法测试授权。本项目仅供安全研究与授权测试学习交流，作者不承担任何滥用责任。

## 它解决什么问题

- 改个用户 ID / 用户名，想知道响应有什么不同（IDOR / 越权快速验证）
- 只测一条请求，不值得开 Burp
- 想直接复用浏览器里已登录的会话
- 1000 条结果里自动找出少数异常响应

核心流程：打开 DevTools → 选中 Network 里的一条请求 → 标记 `{{FUZZ}}` → 粘贴候选值 → 低速发送 → 自动分析状态码 / 长度 / 跳转 / 正文 / 耗时差异 → 异常置顶。

## 安装（开发者模式加载，约 1 分钟）

1. 下载并解压本项目（或 `git clone`）
2. Chrome 打开 `chrome://extensions`
3. 右上角打开 **开发者模式**
4. 点 **加载已解压的扩展程序**，选择项目根目录（含 `manifest.json` 的那层）
5. 打开任意页面的 DevTools（F12），顶部 Tab 栏会出现 **Diffuzz** 面板

说明：

- 安装时的"读取所有网站上的数据"提示：重放请求需要对任意目标站点的 host 权限，功能必需；本扩展**不向任何外部服务发送数据**，全部处理在本地。
- 浏览器偶尔提示"请停用开发者模式扩展"，关闭该气泡即可，不影响使用。
- 企业托管的 Chrome 若禁用开发者模式（组策略），则无法以此方式安装。

## 使用

1. **选请求**：在页面里正常操作产生请求，Diffuzz 左栏实时列出（也可搜索，或直接粘贴 cURL 导入）
2. **标记变异点**：在 URL / 请求头 / 请求体中选中要变异的文字，点 **标记选中为 FUZZ**（原文会记录下来作为基线）
3. **填 payload**：三种方式——每行手填、数字区间生成、或从**字典库**载入
   - 字典库支持：把当前 Payload 命名保存、从 `.txt` 文件导入（自动去重）、编辑、导出、复用
4. **开始**：先自动发 3 次原始请求建基线，再逐条低速发送（默认 2/s，可调 0.2~5/s）
5. **看结果**：按异常分排序，★ 标记异常；点任意一行看与基线的逐行差异对比
6. **导出**：CSV / JSON

### 异常评分怎么来的

每条响应先做归一化（自动打码时间戳、CSRF token、高熵随机串，可加自定义忽略规则），然后提取指纹（状态码 / 跳转签名 / 归一化长度 / 正文 simhash / 耗时），与基线对比并聚类：

- 状态码不同 → 权重 3.0
- 跳转目标不同 → 权重 2.5
- 正文 simhash 汉明距离 → 满距 4.0
- 长度鲁棒 z 分（中位数 + MAD）→ 最高 4.0
- 耗时鲁棒 z 分 → 最高 2.0

### 安全限制（硬编码，不可关闭）

- 目标 host 与导入请求锁定同源，payload 导致 host 变化的条目自动跳过
- 仅 http/https；内网/本地地址默认拒绝（可在面板显式勾选允许，供自建靶机用）
- 单任务 ≤10000 请求（payload 自动去重），请求体 ≤512KB，单响应 ≤2MB（正文截断存储控内存）
- 速率下限 0.2 req/s；连续网络错误或 429/503 自动暂停等待人工确认

## 本地开发与测试

```bash
# 核心逻辑单测（26 项，无需浏览器）
node test/run.mjs

# 启动本地靶机（验收用）
node test/server.mjs 8787
# 然后浏览器访问 http://127.0.0.1:8787 ，记得在 Diffuzz 设置里勾选"允许内网目标"
```

靶机端点：`/api/user/:id`（1337=正文异常，1=302 跳转，1000-1099=正常，其余 404）、`/api/echo`（时间戳/CSRF 噪声，验收归一化）、`/api/slow`（耗时信号）、`/api/ratelimit`（第 11 条起 429，验收自动暂停）。

浏览器端单测：打开 `test/runner.html`。

## 已知限制

- `redirect: 'manual'` 模式下 Chrome 返回 opaque-redirect，读不到 Location 细节；默认使用"跟随跳转"，通过最终 URL 判定跳转。
- 部分流式上传的 POST 请求 HAR 中拿不到请求体，面板会显示为空，需手动补全。
- Service Worker 被浏览器回收会导致运行中任务中断（正常速率下不会发生），面板会提示重新发起。

